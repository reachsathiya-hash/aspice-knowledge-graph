# ASPICE PAM 4.1 Knowledge Graph
**Open knowledge graph of Automotive SPICE® PAM 4.1 + CS PAM 2.0**

Built by: Sathiya Ramamoorthy  
Status: Work in Progress  
License: MIT

---

## What This Is

A structured knowledge graph of the Automotive SPICE® Process Assessment Model 4.1
and the Cybersecurity Engineering PAM 2.0 — making both standards queryable by
quality engineers and ASPICE assessors without reading 200-page PDFs.

---

## Folder Structure

```
aspice-kg/
├── schema/
│   └── aspice_schema.md          ← Schema definition (nodes, relationships, properties)
├── scripts/
│   ├── 01_extract_schema_csv.py  ← Generates seed CSV files from schema
│   └── 02_validate_graph.py      ← Validates extracted graph CSVs
├── data/
│   ├── nodes_seed.csv            ← Seed nodes (generated by script 01)
│   ├── relationships_seed.csv    ← Seed relationships (generated by script 01)
│   └── validation_report.md      ← Validation results (generated by script 02)
└── README.md
```

## Prerequisites

You need:
- Python 3.10 or higher
- A Neo4j AuraDB Free account → https://neo4j.com/cloud/aura/
- An OpenAI API key → https://platform.openai.com (for LLM Graph Builder)
- ASPICE PAM 4.1 PDF (from VDA QMC → https://www.vda-qmc.de)
- CS PAM 2.0 PDF (from VDA QMC → same site)

Install Python dependencies:
```bash
pip install pandas pdfplumber
```

## Step-by-Step Instructions

---

### STEP 1 — Clone This Repository

```bash
cd ~/Desktop
git clone https://github.com/YOUR_USERNAME/aspice-knowledge-graph
cd aspice-knowledge-graph
```

---

### STEP 2 — Run the Seed Extraction Script

This generates the schema-based seed CSV files from the defined ontology.
It does NOT read the PDFs yet — that is done by the LLM Graph Builder in Step 5.

```bash
python3 scripts/01_extract_schema_csv.py
```

Expected output:
```
✓ nodes_seed.csv       : 108 nodes
✓ relationships_seed.csv: 110 relationships
✓ extraction_report.md  : written
```

Open `data/nodes_seed.csv` and verify:
- 38 Process nodes present (ACQ.4 through SEC.4)
- 9 ProcessAttribute nodes present (PA 1.1 through PA 5.2)
- 6 CapabilityLevel nodes present (CL0 through CL5)
- Annex D traceability pairs present in relationships_seed.csv

---

### STEP 3 — Create Your Neo4j AuraDB Database

1. Go to https://neo4j.com/cloud/aura/
2. Click **Start Free**
3. Sign up and confirm your email
4. Click **New Instance** → choose **AuraDB Free**
5. Name it: `aspice-knowledge-graph`
6. When created, you see a one-time credentials screen:
   - **URI**: looks like `neo4j+s://xxxxxx.databases.neo4j.io`
   - **Username**: `neo4j`
   - **Password**: auto-generated string

**Save these now. They appear only once.**

Save them to a file on your Desktop called `neo4j-credentials.txt`

---

### STEP 4 — Configure the Schema in LLM Graph Builder

1. Go to https://llm-graph-builder.neo4jlabs.com
2. Enter your Neo4j credentials → Click **Connect**
3. Click the **Settings** or **Schema** icon (gear icon, top right)
4. Enter these exact Node Labels (one per line):

```
Document
ProcessCategory
ProcessGroup
Process
BasePractice
ProcessOutcome
InformationItem
DomainCharacteristic
CapabilityLevel
ProcessAttribute
ProcessAttributeAchievement
GenericPractice
Note
```

5. Enter these Relationship Types (one per line):

```
SUPPLEMENTS
DEFINES
EXTENDS_PROCESS_GROUP
PART_OF
BELONGS_TO
HAS_OUTCOME
HAS_BASE_PRACTICE
PRODUCES
USES
SATISFIES
DEMONSTRATED_BY
HAS_ACHIEVEMENT
HAS_GENERIC_PRACTICE
ACHIEVES
CROSS_REFERENCES
HAS_NOTE
REQUIRES_FOR_LEVEL
APPLIES_TO
HAS_EXTENSION
BIDIRECTIONAL_TRACEABILITY
CONSISTENCY
```

6. Click **Save Schema**

---

### STEP 5 — Load the Seed CSV Into Neo4j

Before running LLM extraction, load the seed data so the known
structural nodes (Processes, PAs, CLs, Annex D) are already correct.

In Neo4j Browser (from AuraDB dashboard → Open):

Paste and run this Cypher to confirm the DB is empty first:
```cypher
MATCH (n) RETURN count(n)
```

Then import the seed nodes and relationships via the LLM Graph Builder
import feature, or paste the CSV path directly if using Neo4j Desktop.

---

### STEP 6 — Upload PDFs and Run LLM Extraction

In LLM Graph Builder:

1. Click **Add Sources** → **Upload Files**
2. Upload `Automotive-SPICE-PAM-v41.pdf`
3. Upload `AutomotiveSPICECSPAM20Final.pdf`
4. Enter your OpenAI API key in the settings
5. Click **Generate Graph**

This takes 30–90 minutes. The LLM reads the PDFs and extracts:
- BasePractices and their descriptions
- ProcessOutcomes per process
- InformationItems from Annex B
- Notes attached to base practices
- GenericPractices from Chapter 5
- ProcessAttributeAchievements from Chapter 5

**Estimated API cost: €5–10 total**

---

### STEP 7 — Export the Graph as CSV

After extraction completes in Neo4j:

1. Go to Neo4j Browser
2. Run these two queries and export results as CSV:

**Export nodes:**
```cypher
MATCH (n)
RETURN labels(n)[0] AS label,
       n.id AS id,
       n.name AS name,
       n.source_document AS source_document,
       n.purpose AS purpose,
       n.description AS description,
       n.characteristics AS characteristics
```
Save as: `data/nodes.csv`

**Export relationships:**
```cypher
MATCH (a)-[r]->(b)
RETURN a.id AS from_id,
       type(r) AS relationship_type,
       b.id AS to_id,
       r.established_by AS established_by,
       r.rating_required AS rating_required
```
Save as: `data/relationships.csv`

---

### STEP 8 — Run the Validator

```bash
python3 scripts/02_validate_graph.py \
    --nodes data/nodes.csv \
    --rels  data/relationships.csv
```

Read the output carefully:
- **READY** = graph passed all checks → proceed to Step 9
- **NOT READY** = fix the listed failures → re-export and re-run

The validator checks 27 rules across three layers:
- Layer 1: Structural (ID formats, required fields, no duplicates)
- Layer 2: Ontological (allowed connections, cardinality rules)
- Layer 3: Domain fidelity (all 38 processes, Annex D, PA model)

---

### STEP 9 — Manual Domain Validation

After the validator passes, do a manual review:

Open `data/validation_report.md` and check the Review Flags section.

For each flagged process with fewer than 3 BasePractices:
1. Open the PAM PDF
2. Count how many BPs the process actually has
3. Query Neo4j: `MATCH (p:Process {id:"SWE.1"})-[:HAS_BASE_PRACTICE]->(bp) RETURN bp`
4. If BPs are missing, add them manually in Neo4j Browser

Track your findings in this table (copy to your README):

| Process | Expected BPs | Extracted BPs | Status |
|---|---|---|---|
| SWE.1 | 6 | ? | Review |
| SWE.2 | 4 | ? | Review |
| MAN.3 | 7 | ? | Review |
| ... | | | |

## Known Limitations

1. CS PAM 2.0 was written against PAM 4.0. Minor gaps may exist vs PAM 4.1.
2. LLM extraction may miss some Notes or misclassify node types.
3. InformationItem characteristics from Annex B require manual verification.
4. Graph is for decision-support only — not a substitute for assessor judgment.
